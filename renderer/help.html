RelinkDB

Help and setup guide

Start the app, configure Render, and run the relink flow.

Settings Dashboard

1. Start the app

  1. Double-click Start RelinkDB.cmd in this folder for the simplest launch.
  2. For a normal desktop-style app, run npm run package:portable.
  3. Then run npm run desktop:shortcut to place RelinkDB on your Desktop.
  4. After that, open RelinkDB from the Desktop shortcut like any other Windows app.

2. Settings guide

  • Render API Key: create this in Render Account Settings.
  • Database Name: use the exact DB name you recreate every cycle.
  • Web Service ID: the backend service ID from the Render URL.
  • Env Var Key: usually DATABASE_URL.
  • Notification Email: where renewal alerts should be routed.
  • Backup File Path: where the SQL export is written and restored from.

3. Normal monthly flow

  1. Open the dashboard and confirm the expiry countdown.
  2. Click Pull Latest Data while the current DB is still alive.
  3. Click Recreate Database only when you are ready to open Render.
  4. Create the new free Postgres DB in Render with the same name.
  5. Return to RelinkDB and click Restore & Relink.

4. Launch on login

Enable Launch RelinkDB when I sign in from Settings. The app opens visibly on Windows login so the countdown and next action are easy to find.

5. Cloud notifications

The cloud worker can check expiry daily and export once when the warning window opens. The notification payload includes your configured email so each person can route alerts to their own inbox or webhook workflow.

Worker command: npm run cloud:expiry

6. Troubleshooting

  • If email does not appear after saving, reopen Settings and check the field value.
  • If backup or restore mentions psql or pg_dump, install PostgreSQL client tools.
  • If Test Connection fails, verify the API key, DB name, and Render service ID.
  • If the Desktop shortcut fails, rebuild with npm run package:portable.
